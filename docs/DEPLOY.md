# Публикация и настройка «Семейных финансов»

Пошаговая инструкция: от кода на компьютере до иконки на рабочем столе iPhone. Приложение работает на **Vercel** (хостинг), данные хранятся в **Neon** (облачный Postgres). Оба сервиса бесплатны для такого объёма.

Порядок важен: сначала база и секреты, потом миграции, потом деплой.

---

## 0. Что понадобится

- Аккаунт на GitHub с репозиторием `vitaliy-nekrasov/finance`.
- Аккаунт на [Neon](https://neon.tech) (можно войти через GitHub).
- Аккаунт на [Vercel](https://vercel.com) (тоже через GitHub).
- На компьютере: Node 20 и рабочая копия проекта с установленными зависимостями (`npm ci`).
- `openssl`, чтобы сгенерировать секрет. На Linux и macOS он уже есть.

---

## 1. Отправить код на GitHub

Vercel берёт код из GitHub, поэтому всё, что должно попасть на сайт, нужно запушить:

```bash
git switch main
git push origin main
```

Проверьте на github.com, что последние коммиты на месте.

---

## 2. Создать базу в Neon

1. В Neon нажмите **New Project**.
2. **Region:** выберите ближайший к Украине, например **AWS Europe Central (Frankfurt)**. Тот же регион потом укажете в Vercel (шаг 6), чтобы запросы не летали через океан.
3. Postgres-версию оставьте по умолчанию.
4. После создания откройте **Connection Details** (кнопка **Connect**) и скопируйте строку подключения. Она выглядит так:

   ```
   postgresql://user:password@ep-xxxx.eu-central-1.aws.neon.tech/neondb?sslmode=require
   ```

   Это значение для `DATABASE_URL`. Держите его в секрете: в нём пароль от базы.

> На бесплатном тарифе Neon «засыпает» базу после нескольких минут простоя. Первый запрос после паузы может занять секунду-две, дальше всё работает быстро.

---

## 3. Подготовить логин, пароль и секрет сессии

Приложение рассчитано на одного общего пользователя: логин и пароль задаются в переменных окружения, регистрации нет.

### 3.1. Логин

Придумайте логин, например `family`. Это значение для `AUTH_USERNAME`.

### 3.2. Хэш пароля

Сам пароль нигде не хранится, только его хэш. В папке проекта выполните:

```bash
npx tsx scripts/hash-password.ts 'ваш-пароль'
```

Скрипт выведет строку вида:

```
scrypt:3f1a…:9c0b…
```

Вся эта строка целиком, вместе с `scrypt:` и двоеточиями, и есть значение для `AUTH_PASSWORD_HASH`.

- Пароль берите в одинарные кавычки, чтобы shell не обработал символы `$`, `!` и т. п. Если в самом пароле есть одинарная кавычка, проще выбрать другой пароль.
- Каждый запуск даёт новую строку (соль случайная), это нормально: подходит любая из них.

### 3.3. Секрет сессии

```bash
openssl rand -base64 32
```

Результат — значение для `SESSION_SECRET`. Он должен быть не короче 32 байт: со строкой из этой команды всё в порядке. Если секрет короче или не задан, вход работать не будет.

### 3.4. Сохраните четыре значения

Запишите их в менеджер паролей, они понадобятся на шагах 4 и 6:

| Переменная | Откуда |
|---|---|
| `DATABASE_URL` | Neon, шаг 2 |
| `AUTH_USERNAME` | шаг 3.1 |
| `AUTH_PASSWORD_HASH` | шаг 3.2 |
| `SESSION_SECRET` | шаг 3.3 |

## 4. Создать таблицы в базе (миграции)

База в Neon пока пустая. Таблицы создаются миграциями из папки `drizzle/`.

`drizzle-kit` не читает `.env`-файлы, поэтому строку подключения нужно передать явно. Вариант 1, прямо в команде:

```bash
DATABASE_URL='postgresql://…neon.tech/neondb?sslmode=require' npx drizzle-kit migrate
```

Вариант 2: если `DATABASE_URL` уже записан в `.env.local`:

```bash
node --env-file=.env.local node_modules/.bin/drizzle-kit migrate
```

> Если вы пишете продакшен-`DATABASE_URL` в `.env.local`, то и локальный `npm run dev` начнёт работать с продакшен-базой, а не с локальной PGlite. Для локальной разработки удобнее держать `DATABASE_URL` в `.env.local` пустым и пользоваться вариантом 1.

Команда должна завершиться без ошибок. Проверить можно в Neon → **Tables**: там появятся `uploads`, `accounts`, `transactions`, `upload_transactions`, `login_attempts`.

## 5. Подключить проект в Vercel

1. В Vercel нажмите **Add New… → Project** и выберите репозиторий `finance` (при первом разе Vercel попросит доступ к GitHub).
2. **Framework Preset** определится сам: Next.js. Build и Install команды оставьте по умолчанию.
3. Разверните **Environment Variables** и добавьте четыре переменные из шага 3.4. Значения вставляйте как есть, без кавычек.
4. Нажмите **Deploy**.

> **Preview-деплои.** Vercel собирает отдельную версию сайта для каждой ветки и PR. Если переменные заданы и для окружения **Preview**, такие версии будут работать с той же продакшен-базой. Если это не нужно, оставьте переменные только для **Production**: preview-версии тогда просто не пустят на вход.

---

## 6. Регион функций в Vercel

По умолчанию серверный код Vercel работает в США, а база — во Франкфурте, и каждая страница будет ждать запросы через океан.

1. Откройте проект → **Settings → Functions → Function Region**.
2. Выберите **Frankfurt, Germany (fra1)**, то есть тот же регион, что у базы.
3. Сохраните и сделайте **Redeploy** (Deployments → ⋯ у последнего деплоя → Redeploy), чтобы настройка применилась.

## 7. Проверить, что всё работает

Откройте адрес сайта, его показывает Vercel, вида `https://finance-xxxx.vercel.app`.

- [ ] Без входа открывается страница `/login`.
- [ ] Вход с вашим логином и паролем проходит, открывается «Обзор» с предложением загрузить выписки.
- [ ] На странице «Загрузка» принимается Excel-выписка Привата или monobank, после загрузки на обзоре появляются суммы и категории.
- [ ] Неверный пароль даёт «Неверный логин или пароль». После 5 неудачных попыток с одного адреса вход блокируется на 15 минут: так и задумано.

Сессия живёт 90 дней, потом нужно войти заново.

## 8. Установить на iPhone

1. Откройте сайт в **Safari** (именно в Safari, не в Chrome) и войдите.
2. Нажмите **«Поделиться»** → **«На экран Домой»** → **«Добавить»**.

На рабочем столе появится иконка со стеклянной плиткой и знаком «₴». Приложение откроется во весь экран, без адресной строки.

Если вы поменяли иконку в коде, iOS её не обновит: она запоминает картинку в момент добавления. Удалите значок с рабочего стола и добавьте заново после деплоя.

## 9. Как выпускать обновления

**Обычное изменение** (без изменения схемы базы): закоммитьте и запушьте в `main`, Vercel соберёт и выложит новую версию сам за 1–2 минуты.

**Изменение схемы базы** (`src/db/schema.ts`):

1. Сгенерируйте миграцию: `npx drizzle-kit generate`. Появится новый файл в `drizzle/`, закоммитьте его.
2. **До** пуша в `main` примените миграцию к Neon, как в шаге 4.
3. Запушьте код.

Если запушить код раньше миграции, новая версия сайта будет обращаться к колонкам, которых ещё нет, и упадёт.

## 10. Безопасность и обслуживание

- **Выйти на всех устройствах.** Кнопка выхода удаляет cookie только в текущем браузере. Чтобы закрыть все сессии разом, сгенерируйте новый `SESSION_SECRET` (шаг 3.3), замените его в Vercel (Settings → Environment Variables) и сделайте Redeploy.
- **Сменить пароль.** Сгенерируйте новый хэш (шаг 3.2), замените `AUTH_PASSWORD_HASH` в Vercel и сделайте Redeploy. Старые сессии при этом продолжат работать: если нужно их закрыть, смените ещё и `SESSION_SECRET`.
- **Ограничение попыток входа** опирается на заголовок `x-forwarded-for`, который проставляет Vercel. Если когда-нибудь переедете на другой хостинг, убедитесь, что этот заголовок выставляет доверенный прокси, иначе ограничение можно обойти.
- **Выписки не хранятся.** Исходные файлы нигде не сохраняются. Из шапки monobank в базу попадают только маски карт, IBAN и период.
- **Утечка `DATABASE_URL`.** Если строка подключения могла попасть к посторонним, сбросьте пароль роли в Neon (Roles → Reset password), обновите `DATABASE_URL` в Vercel и сделайте Redeploy.

## 11. Сверка на реальных выписках

После первого запуска стоит один раз вручную сверить приложение с реальными файлами Привата и monobank (своими и жены). Удобнее делать это локально: положите файлы в `samples/` (в git не попадает), запустите `npm run dev`, загрузите их и проверьте:

- [ ] число операций в приложении совпадает с числом строк в файлах (с учётом пропущенных валютных счетов и дублей);
- [ ] итог месяца (доходы, расходы) совпадает с суммой, посчитанной вручную;
- [ ] найденные «переводы между своими» действительно переводы между своими картами, а не платежи третьим лицам;
- [ ] включена ли комиссия monobank в «Сума в валюті картки». Если нет, её нужно добавить в сумму в `parseMono` вместе с тестом.

Найденные расхождения превращайте в тесты на обезличенных данных и исправляйте.

## 12. Если что-то не работает

| Что видно | Вероятная причина | Что сделать |
|---|---|---|
| Страница входа открывается, но после нажатия «Войти» — ошибка сервера | Не задан `DATABASE_URL` или `SESSION_SECRET` (либо секрет короче 32 байт) | Проверить обе переменные в Vercel, Redeploy |
| «Неверный логин или пароль» при верных данных | Хэш вставлен не целиком или с кавычками; опечатка в `AUTH_USERNAME` | Вставить строку `scrypt:…` полностью, без кавычек, Redeploy |
| «Слишком много попыток» | 5 неудачных входов за 15 минут | Подождать 15 минут |
| Ошибка про отсутствующую таблицу или колонку | Миграции не применены к Neon | Шаг 4 |
| «Файл больше 4 МБ» | Выписка слишком большая | Выгрузить из банка период покороче |
| «Не удалось распознать выписку» | Файл не Excel-выписка Привата или monobank | Скачать выписку в формате Excel (.xls/.xlsx) из банка |
| Страницы открываются медленно | Регион функций Vercel не совпадает с регионом базы; или база Neon «проснулась» после простоя | Шаг 6; первая загрузка после паузы — норма |

После изменения переменных окружения в Vercel всегда нужен **Redeploy**: уже собранная версия старые значения не перечитывает.
